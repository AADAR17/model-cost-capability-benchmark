## Description
Adds strict validation to `base64.b64decode()` calls across multiple files, closing a gap where invalid base64 input was silently tolerated instead of rejected.

## Diff

### django/contrib/auth/hashers.py
```
- salt = base64.b64decode(b64salt).decode("latin1")
+ salt = base64.b64decode(b64salt, validate=True).decode("latin1")
```

### django/core/cache/backends/db.py
```
- value = pickle.loads(base64.b64decode(value.encode()))
+ value = pickle.loads(base64.b64decode(value.encode(), validate=True))
```

### django/db/models/fields/__init__.py
```
+ import binascii
+ default_error_messages = {"invalid": ...}
# to_python() now wraps b64decode() in try/except, raising ValidationError
# on UnicodeEncodeError or binascii.Error
```

### django/http/multipartparser.py
```
- base64.b64decode(raw_data)
+ base64.b64decode(raw_data, validate=True)
- base64.b64decode(stripped_chunk)
+ base64.b64decode(stripped_chunk, validate=True)
```

### tests/urlpatterns/converters.py
```
- return base64.b64decode(value)
+ return base64.b64decode(value, validate=True)
```

### Other changes
- **docs/releases/6.1.txt**: release notes on stricter Base64 validation
- **tests/file_uploads/tests.py**: `test_base64_invalid_upload()` now expects `MultiPartParserError`
- **tests/model_fields/test_binaryfield.py**: new `test_invalid_data()`
